12 Getting Started
The DynamicStudio Image Acquisition System comprises the DynamicStudio software including
on-line image acquisition. The acquisition system can be configured with the desired parameter set-
tings and data can be acquired, pre-viewed and saved to disk at the operator needs.
A comprehensive number of data processing methods are available for analyzing the data after the
acquisition has been made and the data are saved to disk.
Normally the acquisition hardware used to control the camera and illumination system (typically a
laser), hardware synchronization and data acquisition/transfer are installed in the same PC as the
DynamicStudio software.
The system supports a multitude of different cameras and can be configured for one or more cam-
eras (typically using multiple cameras of the same type).
A synchronization unit is used to generate trigger pulses for all cameras, light sources and/or a shut-
ter devices.
For more information about supported devices please see "Cameras" on page 210, "Syn-
chronizers" on page 315, and "Illumination Systems" on page 405.
12.1 Warranties and Disclaimers
12.1.1 Camera Sensor Warranty
Direct or reflected radiation from Argon or Nd:YAG lasers can damage the sensor of the camera.
This may happen with or without power to the camera and with or without the lens mounted. There-
fore when setting up and aligning for measurements, take extreme care to prevent this from hap-
pening.
Laser damage may turn up as white pixels in the vertical direction, or as isolated white pixels any-
where in the image. This shows up clearly when acquiring an image with the lens cap on.
The manufacturer has identified all sensor defects into classes. Often the character and location of
all defects are on record. Additional defects arising from laser-induced damage may void the
sensor warranty.
Precautions
1. Cap the lens whenever the camera is not in use.
2. Cap the lens during set-up and alignment of the light sheet. Before removing the cap, make
sure that reflections off the surface of any objects inside the light sheet do not hit the lens by
observing where reflections go.
3. As general precautions to avoid eye damage, carefully shield any reflections so that they do not
exit from the measurement area. You must wear appropriate laser safety goggles during laser
alignment and operation.

Database structure
DynamicStudio stores data in a tree structure. The database is at the root of the tree structure,
branching out into one or more project folders. Each project folder can hold both calibration images
and normal images stored in so-called 'Runs'. Every time you transfer data from the image buffer to
the database by saving the acquired images, a new Run is added to the latest project and time
stamped for later reference. All project, run and ensemble labels can be changed later. You can cre-
ate new projects e.g. to separate different experiment configurations.
By right clicking on the different levels of the database, you can access different operations and
properties
PAGE|75
Ensembles
A core feature of DynamicStudio is the concept of ensembles, which represent a series of data as a
single icon in the database. Typically an ensemble corresponds to a Run and can hold anywhere
from a single to thousands of images or derived datasets. This helps navigate the very large
amounts of data that can easily be acquired with modern imaging systems.
The ensemble is the main data type in a DynamicStudio database and analysis methods default to
processing entire ensembles. It is also possible to access and/or process subsets of ensembles by
selecting datasets from the ensemble content. When analyzing an ensemble results are stored in a
new child ensemble that branch off from the parent ensemble in the database tree. In special cases
a single analysis may generate multiple child ensembles from one or more parent ensembles.
These data ensembles are referred to as 'Siblings'.
In the figure in the previous section the topmost ensemble has been renamed to 'Gain 0' and the
text right next to the name indicate that this ensemble contain 50 datasets. From the icon we can
see that the ensemble contain single frame images. Double-clicking the ensemble icon displays the
1st image in the ensemble. To inspect individual images in an ensemble, right click the ensemble
and select Contents from the resulting context menu:
Browsing inside the contents list the display window will update accordingly to show individual data-
sets in the ensemble.
Project
The database can be fragmented into projects. For example a project can correspond to a specific
flow setup configuration.
Calibration
A calibration folder will always be present in a project that contains data. It is recommended to store
images for calibration int this folder. Only one calibration folder per project can be created. From
the ensemble under the calibration, the specific operations are:
l To Define Origin and Scale
l To perform a calibration
l To pre-process images (Image Processing Library and Image arithmetic)

Run
When acquired images are stored, a new run will be created to contain the ensemble of stored data-
sets. The analysis tools (among other things) are available in the ensemble right click menu as well
as the analysis tab in the ribbon
Deleting, Duplicating or Moving ensembles
Any ensemble can be deleted from the database, by selecting it and pressing the 'Delete' key.
Please note that child datasets will be deleted as well. The user will be asked to confirm once more
before the data is actually deleted to avoid doing so by mistake. If the data about to be deleted was
used as input to other analyses elsewhere in the database the user will be warned about this in the
prompt to confirm if the data is to be deleted.
Via 'Show Contents List' from the Context menu it is also possible to select and delete individual
datasets from the ensemble, but only if the ensemble in question does not have child ensembles.
From the context menu it is also possible to 'Duplicate' an ensemble, i.e. create a copy of the same
data. This can be useful to compare analysis results with different recipe settings or try a new ana-
lysis on the same data without mixing it up with analysis results previously computed. The duplicate
ensemble will be added as a new child of the same parent, child data are not copied when a duplic-
ate is made of their parent.
Ensembles that do not have children can also be moved between runs or projects or from e.g. a nor-
mal run to the calibration folder by a simple click and drag operation with the mouse. It is not pos-
sible to move data the other way from the calibration folder to a normal run.
When moving data between runs the settings such as time between frames, camera count and so
on MUST be the same in the source and destination runs.
Warning: Moving data around in the database may lead to loss of information, such as dependency
between various datasets and it may thus corrupt the database. Moving ensembles is entirely the
users responsibility, not recommended and should be done only in extreme necessity.

12.3.4 Delete and Restore
When enabled, the database feature 'Delete and Restore' will enable a 'Waste Bin', where items
deleted from the database are temporarily stored, providing the option to restore the data to their
original location in the database.
By default 'Delete and Restore' is enabled, but it can be disabled via DynamicStudio Options.
If 'Delete and Restore' is enabled, data deleted from DynamicStudio databases are not immediately
deleted, but moved to a Waste Bin named 'Deleted Items'. If the deletion was a mistake it is pos-
sible to restore the deleted items to their original location in the database.
Deleted Items record
When 'Delete and Restore' is enabled a record named 'Deleted Items' will appear in the database
tree just below the root database icon.
When the feature is first enabled the waste bin will be empty as shown by the icon in the left of the
two figures above. Once data have been deleted (and thus moved to the waste bin) the icon will
change to the one shown on the right, indicating that the waste bin contains items, which can poten-
tially be restored.
The properties of the Deleted Items record will indicate how much data is in the waste bin:
Indicate parents to deleted items
When data is deleted the parent record is marked in the database tree with a small indicator. This
tells the user that deleted child items are in the waste bin, from where they can be restored.
The indicators can be toggled on and off by pressing Ctrl-I, or by right-clicking the waste bin and
selecting "Indicate parents to deleted items" or "Do not Indicate parents to deleted items". By
default the indicators are on.
Restoring deleted items

12.3.6 Coordinate System
DynamicStudio is intended for imaging, where cameras are used to measure things.
Tracking for example the movement of a particle from one image to another is of little use finding
only that the particle moved e.g. 4.8 pixels to the right and 1.3 pixels down. If on the other hand the
distance between neighboring pixels is known to correspond to e.g. 2mm in the light-sheet where
the particle was, it can be inferred how far it moved in metric units.
Finally a global coordinate system is required to say exactly where the particle was when the
images were acquired.
Likewise knowing the time between consecutive images will allow the measured displacements to
be converted to estimated velocities, but identifying when the measurement took place requires a
global timescale.
The acquisition system generally takes care of all timing including synchronization of various
devices and also assign accurate timestamps to all acquired images.
The acquisition system does however not have information about the geometry of the image acquis-
ition system so a calibration is required to assign spatial coordinates. Typically this involves the
acquisition of "Calibration Images" on page 115 of a dedicated target or at least an object with dis-
tinct features where the locations and/or distance between them is known. If always the same set-
up with all distances fixed to each other, always the same camera parameters are used, the scale
factor and the origin can also be defined in the "Origin and scale definition" on page 95.
For single camera systems such as classic 2D-PIV, where the camera is looking at a light-sheet at
right angles, it is often sufficient to "Measure scale & define origin" on page 92. A dedicated cal-
ibration target can be used for this, but an object of known size can also be used provided there are
corners or other distinct features that can easily be identified on the image.
PAGE|84
For measurements in a plane such as a lightsheet, the calibration target should of course be
aligned with the lightsheet, where the measurements are made.
A common global coordinate system is required for multi-camera systems or single camera setups,
where the camera is not normal to the lightsheet so perspective effects need to be accounted for.
When perspective and/or distortion is involved Scale Factor varies across the cameras Field of
View and a full camera calibration is required, using a dedicated calibration target with markers in
known and well defined positions that cover as much as possible of the cameras field of view.
The target can be an "Active Target" (on page 440), turning individual markers on and off in a con-
trolled manner or it can be a passive target, where all markers are illuminated at the same time. Tar-
gets can be chessboard or dot matrix style, single-sided or double-sided and they can be planar or
multilevel. Several known targets of varying types and sizes are in the target library or users can
enter parameters of a custom target of their own.
Camera calibration is a two-step process, where calibration markers are first identified and located
on a series of calibration images. Once a list of corresponding object-space and image-plane
coordinates has been established the second step is to fit a mathematical model to the list of mark-
ers found. There are several such Imaging Models to choose from, each with a number of para-
meters to describe a mapping from object space to image plane. Since Camera Calibration aim to
determine these parameters it is also referred to as an Imaging Model Fit, IMF.
Both the marker identification and the imaging model fit is performed by "Multi Camera Calibration"
on page 765.
Calibration Models in DynamicStudio
An imaging model is a mathematical model that describes how points in 3-D "Object Space" are
transferred to the 2-D "Image Plane". Object space coordinates are typically measured in metric
units such as mm and Image plane coordinates are typically measured in pixel as the camera
sensor defines the image plane.
Depending on the choice of imaging model the transformation may describe perspective, lens dis-
tortion (e.g. barrel or pincushion distortion) or some other arbitrary spatial distortion. All imaging
models have a number of parameters and determining the value of these parameters in a specific
image acquisition setup is referred to as "Camera Calibration" or "Imaging Model Fit", since para-
meters are fitted to give the best possible match between corresponding coordinates in object
space and image plane.
A full 3D model describes how points in the object space (world) are mapped onto the image plane
(sensor) of the camera, while a 2D model describes only the mapping of points from the object
plane (light-sheet) to the image plane. 2D imaging models are often cropped 3D models ignoring
some of the parameters or simply setting them to zero.
3D models generally require a multilevel target or multiple images of a planar target in different pos-
itions and/or orientations.
2D models can be based on a single image of a planar target.
DynamicStudio supports a number of imaging models, each with their strengths and weaknesses.
"Direct Linear Transform (DLT)" (on page 659)
Direct linear transform is a linear affine transform to describe position, orientation, scaling and per-
spective.
It is a strictly linear transform, unable to model any non-linear distortions.
"3'rd order XYZ polynomial imaging model fit" (on page 660)
A polynomial in 3D that will map the object space to the image plane.
PAGE|85
This model is purely empirical and does not relate to physical measures like position and ori-
entation of the camera in object space.
It is capable of handling severe distortion caused by the lens and/or refraction in air/water inter-
faces (windows).
With a multilevel target only 2 Z-levels are available so the model is restricted to be 1st order (lin-
ear) in Z.
Extrapolation beyond the target markers found is not advised with the polynomial model, it is likely
to diverge very quickly.
"Pinhole camera model" (on page 662)
The pinhole model is an idealized physical model of a camera, including parameters to describe
position and orientation of the camera plus other parameters to describe radial and tangential dis-
tortions.
It is the only model capable of estimating a full 3D mapping based on a single image of a planar tar-
get, but this is inaccurate and not recommended. Multiple images of a traversed target is much bet-
ter. Alternatively this model supports a pan/tilt approach, where a series of images are acquired
with the target in random positions and orientations. One of these, typically the first, is considered
the reference, determining the coordinate system.
In general this model requires more images than the others.
"Telecentric camera model" (on page 665)
Mathematically identical to the Pinhole camera Model, with some constraints to handle Imaging
without perspective
Capable of describing Telecentric Lenses without perspective.
Requires multiple images from multiple cameras/views and thus available only via 'Multi-Camera
Calibration'
The calibration target contain markers that defines the object coordinate system and proper illu-
mination is required to ensure that all markers are clearly visible on the recorded image(s). Please
verify also that the calibration markers covers as much as possible of the cameras field of view.
Moving the camera or the light-sheet or otherwise changing the image recording setup will require
the imaging model parameters to be recomputed.
For some imaging models the parameters can in principle be calculated from known angles, dis-
tances, etc, but in practice this approach is not feasible. In the actual laboratory setup it is often dif-
ficult if not impossible to measure these angles, distances and so on with sufficient accuracy.
Therefore all imaging model fits require images of a calibration target, which are analyzed to
determine the imaging model parameters.
2D imaging models requires that the calibration target is aligned with the light sheet and usually a
single image is sufficient.
For a full 3D imaging model you must either use a multilevel target or acquire multiple images of a
plane target positioned in front of, centered in and behind the light-sheet. In at least one of these
images the target should be aligned with the lightsheet and with the origin at the desired position.

Multi Camera Calibration
The Multi Camera Calibration method is used to generate spatial camera calibrations, a.k.a. IMF's,
Imaging Model Fits, for each of the cameras in the system.
As implied by the name it is designed to calibrate multiple cameras at the same time, but they can
also be calibrated one by one.
It is based on multiple images of a calibration target with markers in known positions. The target
can be active, turning individual markers on and off in a controlled manner or it can be passive,
where all markers are illuminated at the same time. Targets can be chessboard or dot matrix style,
single-sided or double-sided and they can be planar or multilevel. Several known targets of varying
types and sizes are in the target library or users can enter parameters of a custom target of their
own.
Often the target is traversed to cover a volume, but in some cases a pan/tilt approach can be used
with just one well-defined reference target position and orientation, followed by a series of images
where the target has been moved and/or tilted randomly to cover the intended measuring volume.
The Multi Camera Calibration method provides a fully automatic or alternatively a semi-automatic
calibration, which automatically detects individual markers but the user still has the possibility to
manually specify the origin of the calibration target. In addition, also a Manual Calibration is
provided that lets the user freely create a calibration grid with markers, to be manually placed on
top of the calibration images in order to relate the dimensions of the image to a coordinate system
in physical space.
The input requirements for the method is either single a calibration image ensemble or multiple cal-
ibration image ensembles from multiple cameras, which are then selected as fixed inputs. For

12.3.10 Ensemble Linking
As implied by the name Ensemble Linking will allow you to 'Link' two or more DynamicStudio data
ensembles such that anything you do to one of the linked ensembles is automatically done to the
others as well. This can be used for Analysis, but is most often used when displaying multiple data-
sets side by side for comparison; The Linked Ensemble display could for example show Input and
Output of some analysis, or represent images from several cameras that were acquired sim-
ultaneously. If you zoom in on a detail in one display the other display(s) will automatically zoom in
on the same area and if you pan one display the other(s) will automatically pan also.
Image pairs acquired with the DualScope will for example be stored as Linked Ensembles by
default so opening (or closing) the display of one will automatically open (or close) the display of
the other also. (Read more about "DualScope" on page 455).
Data from linked ensembles obviously come from different ensembles. If you wish to have multiple
displays of the same data open and close synchronously, use "Group Displays" on page 1055.
To establish the link first select (Ctrl-Click) each of the ensembles that you wish to include in the
link, then right-click either of them and pick 'Link ensembles' in the context menu:
PAGE|112
Small chain symbols will now appear on each ensemble icon in the database to visualize that they
have been linked.
When you open either of the linked ensembles for display the others will automatically be opened
also and display windows be distributed and scaled for synchronized display. Similarly closing
either of these displays will automatically close the others as well. You can in principle link any num-
ber of ensembles, but in most cases you will be comparing 2, 3, 4 or perhaps 6 displays side by
side.
Linked displays work best when all of the display windows involved have the same size. The dis-
play 'Tile' function can be used to achieve this easily.
Please note that linked displays may be out of sync if two or more of the ensembles were already
displayed when the link was established. This can be fixed by selecting a fixed zoom and/or 'Fit con-
tent to Window' in the context menu of either display.
In the example used here, we've linked 4 ensembles for side-by-side comparison; One input image,
one intermediate result and two outputs.
The images are from measurements on arc welding, where PIV seeding has been added to the
shielding gas and droplets of molten metal is also flying around.
Image processing is applied in an attempt to separate the small PIV seeding particles from the
much larger metal droplets so the two can subsequently be analyzed separately.
Despite narrow band filtering the welding process itself generates a lot of background noise so the
first step attempts background removal, leading to an intermediate result where seeding particles
and metal droplets remain mixed, but background intensity has been reduced. Further processing
of this leads to separate images with large and small objects respectively. Ensemble linking is used
to quickly and easily zoom in on different image regions to assess how well the analysis performs
and perhaps see where it fails and thus needs modification.
Top left is the input image, bottom left has the background removed. Top right is the large objects
(i.e. the metal droplets) and bottom right is the small objects (i.e. PIV seeding particles in the shield-
ing gas):

the background removal takes care of the secondary scattering from this object:
PAGE|114
From there panning to the top right corner shows that the large objects are indeed in the top right
image, while the bottom right one contain only small objects:
